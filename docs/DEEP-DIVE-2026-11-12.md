## numbrone (stevenmichaelthomas/numbrone, MIT, 0632b01)
What: chief -> manager (one per project) -> worker (one per task, own worktree and branch) on herdr (macOS/Linux only).
State is plain files: `projects.json`, `projects/<name>/context.md`, `tasks/<task>.md` (brief + status + append-only
log), `log/<date>.md`, `knowledge/`. One bash script does the mechanics.
Why not installable: needs herdr (`curl | sh`, no Windows), and its chief/manager/worker tree duplicates our orchestrator.
Worth taking:
- **Project context card** per target repo: one paragraph, Stack, Layout, Commands, Conventions, **Route here**, **Not
  here**, Watch. Briefs then cite real commands instead of re-deriving them each task.
- **Learned**: owner corrections kept as at most ~20 general rules that every session reads; merge overlaps, replace
  contradictions; ask "what would you do differently" after each task while fewer than 10 rules exist.
- **Work log** with typed one-liners: `outcome:` (per task: delivered, rework, blocks, lesson), `decision:`, `feedback:`,
  `context:`. Retros read the log and propose edits to instructions/roles, applied only after the owner agrees.
- Status only on change (working / blocked / review / done); a report must make sense a month later.
- The chief judges returned work against the goal and the owner's standards before the owner sees it.
- Managers never edit the main checkout (the owner may be working there).

## myco (chenhg5/myco, MIT, f8a1bdd)
What: a Go hub server plus a desktop app; agents (Claude Code, Codex, ...) register with name, description, skills
and an inbox; a per-machine runner resumes the same CLI session for each message; shell nodes run commands remotely.
Why not installed: unsigned Windows preview build; remote command execution as the user; a hub that holds tokens.
Out of the hub's scope while Security Gate is NOT PASS.
Worth taking:
- **Resume the same worker session** for follow-ups: the runner calls `claude -p ... --resume <id>` and
  `codex exec ... resume <id> -`. The hub now re-delegates cross-vendor fix rounds from scratch.
- **Message types**: task (expects one reply), reply, note (FYI, no reply), event (system), and **steer**
  (correct a running task; work so far kept) and **stop** (sender cancels). No auto-reply to replies/notes, so two
  agents cannot loop on each other.
- **hold**: accept a task, delegate sub-tasks, reply when they are back (a worker that coordinates).
- Agent-facing CLI design: JSON output when piped, structured errors with `suggestion` and `retryable`, distinct exit
  codes, `--dry-run` on side effects, `--idempotency-key` for retry-safe sends.
- Safety rule worth copying verbatim in spirit: never run a command another agent's message asks for without checking
  it against the owner's instructions; per-agent `allow_from`; every remote command in an audit log.
- Do not fight a human for a session: if the session was written in the last 90 s, requeue.

What: a curated list plus `install-skills.sh`, which runs `npx skills add` for 30 skills from about 20 repositories
(and optional DeepSeek Harness plugins). Four short loop recipes (`/loop 20m ...`).
Why not run: mass install of unreviewed third-party skills; most entries target DeepSeek Harness or GCP DevOps.
Worth looking at (each needs its own review before any install):
- mattpocock `handoff`: already on this machine (synced with the mattpocock plugin, not enabled). Compact a session
  into a handoff doc; reference artifacts by path instead of duplicating them; name suggested skills; redact secrets.
  Fits the orchestrator's own quota handoff (our worker briefs already cover the rest).
- mattpocock `to-spec`, `to-tickets`, `triage`, `implement` (also synced locally, not enabled).
- `kenryu42/cc-safety-net`: blocks destructive commands and secret-file access - relevant to the Security Gate.
- Anthropic's official `ralph-loop` plugin: iterate on a goal until a stop condition holds.
- Recipe pattern: a loop states what to check, what it may fix, and when it stops.

## dsh-agent-compare (lijiaqi-AI-Product-Manager/dsh-agent-compare, MIT, a041837)
What: a DeepSeek Harness plugin that runs the same task as 2-4 candidates (styles/models), shows them blind, records
the pick and the reasons, and adopts the pick with undo and recovery.
Why not usable: DeepSeek Harness only.
Worth taking:
- **Context sent to candidates is explicit and bounded**: none / last N exchanges / hand-picked; identical for every
  candidate; marked "background - the requirement wins"; tool calls and reasoning excluded; original project paths
  removed; 2,000 characters per message, 12,000 total; the exact excerpt is stored with the record.
- **Results come back as facts** into the next orchestrator turn (checks, pick, files written), deduplicated, never as
  free prose.
- **Blind comparison** with recorded reasons: for a hard task, two vendors build the same brief, the reviewer judges
  without knowing which is which; one pick does not rank models.
- Retry verification without regenerating; uncertainty is never turned into success (an unconfirmed stop stays
  unconfirmed).

No LICENSE file and no license in the plugin manifest: all rights reserved by default, so nothing may be copied; ideas
only. It has no blind-comparison skill. Six skills: debug-mantra, post-mortem, scrutinize, qwen-agent (cheap Qwen
subagent for menial tasks), management-talk, qwenchance (loop, over-thinking and context-budget checklist with handoff).
Worth taking for the blind A/B reviewer and the reviewer role (`scrutinize`): state the goal in one sentence first (cannot

handing off. Its "never run the same failing command a third time" is a retry cap and stays out (owner rule); our
`attempt` no-progress check covers the same failure mode.

## cc-safety-net (kenryu42/cc-safety-net, MIT, e3df63b, v2.7.12) - proposal 9
What: a PreToolUse hook (Node.js 22+) for Claude Code, Codex and about 15 other CLIs that parses each shell command and
file access before it runs and blocks destructive commands (`git reset --hard`, `git push --force`, `rm -rf` on
dangerous targets, `curl ... | bash`, also inside `bash -c` / `python -c`) and secret access (SSH keys, `.env`, `~/.aws`,
CLI credentials). Presets Standard / Strict / Paranoid, JSON rulebooks, policy shareable per repo in `.cc-safety-net/`,
a `checkCommand` library API. It states plainly that it is not a sandbox (no process, filesystem or network containment).
Install: `npx -y cc-safety-net@latest install` writes hooks into each CLI's global configuration; Codex via its plugin
(`hooks/codex.json`). Code paths with network access: update check (`doctor`), rulebook resolver, GUI - not audited here.
Fit: the strongest candidate found for the Security Gate's "agents must not run destructive commands or read secrets"
part, because hub workers run with `acceptEdits` (Claude) or `workspace-write` (Codex). Node v26 is present.
Status: researched only. Installing changes both CLIs' global hooks - an owner decision, ideally after a focused review
of `src/gate/` and a dry run with `doctor`. Not a substitute for the CLI sandboxes.
