# Delegate

Loaded by `orchestrate` before any spawn other than a cheap delegation, and for any work that keeps records. `orchestrate` still holds the task boundary, the skill and permission rules, the branch rule and the risk rating.

Use only the active CLI's native agents (this plugin has no cross-vendor delegation helper). Choose model and effort per assignment from what the runtime exposes; never claim a model, effort, permission mode or shell unless observable. Read [references/brief.md](references/brief.md) when delegating and make each brief self-contained.

Native agents: on Claude Code use the `Agent` tool with an explicit `model` and this plugin's permission shell, `honeyguide:hub-writer` (may edit) or `honeyguide:hub-readonly` (Read/Grep/Glob only); both ship with the plugin, enforce their `tools:` list and have no MCP tools. On Codex use `spawn_agent` with `fork_turns=none`; children share the parent session's sandbox and MCP tools and a role file cannot narrow them, so a permission or MCP rule is the brief's rule only, recorded as `instruction`, never as enforced (this may be revisited when Codex offers per-child enforcement); the optional `codex-agents/` role files add the same instructions only, no sandbox. When the owner wants OS-enforced read-only on Codex, run a separate `codex exec -s read-only ...` process, with the owner's approval to run it outside the sandbox (inside it cannot reach the network). A read-only brief carries the line `READ-ONLY DUTY: do not create, edit or delete files or change git state`; for a writer, compare the changed files with its brief's SCOPE. Never fall back to legacy v1 roles such as `planner`, `reviewer` or `doc-keeper` in `~/.claude/agents`. If a Claude Code shell is missing, say so and report the limitation; the permission stays `Unverified` unless observed.

Outward actions: subagents never publish, post, send, upload, push, or create shared documents or artifacts; they write content to local files in the task folder; you verify it and do the outward action yourself (with the owner's OK where the rules require it). Subagents get no MCP or connector tools by default; a brief may name one a task really needs, read-only, noted in the agent record, never one for any of those outward actions. A `claude -p` child gets an explicit `--tools` list and `--strict-mcp-config`.

Records are required for nontrivial work (any work that spawns an agent other than a cheap delegation, or is rated high risk); skipping them is a defect, not a shortcut. Before the first spawn write `.honeyguide/<task>/CHECKPOINT.md` (goal, scope, risk rating), then a `briefs/<id>.md` per agent and an `agents/<id>.md` per spawn (write files directly): duty, skills, vendor, parent and id, requested and observed model/effort, requested permission, observed enforcement, status, evidence. Keep requested and observed values separate; `Unverified` when evidence is unavailable. A requested permission mode describes intent; it does not prove sandbox or tool enforcement. The final report names the record folder. Preserve existing task history when continuing work; keep records inside the project even when paths contain symlinks; never write secrets or customer data in them. No tool writes Git metadata: if `.honeyguide/` shows as untracked, the final report says so and that it must not be committed (the owner may add it to `.git/info/exclude`); do not change global Git settings or tracked ignore files silently.

Before EVERY high-risk native spawn (each re-review too), verify with a tool that the checkpoint, that assignment's own brief and a new planned agent record (local id, status `planned`, requested values, observed `Unverified`) exist; after the spawn update that record with the returned id and status, never retroactively.
