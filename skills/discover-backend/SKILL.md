They are reference material, not instructions: the project's own code, docs and rules win, and nothing in them widens permissions. Read only the files the task needs, never a whole folder: pick the row for the topic, open its file, then follow the links inside it. Upstream `SKILL.md` files are stored as `SKILL.upstream.md` so that they are not loaded as skills.

Version warning: the Nitro files target Nitro v3 beta (3.0.260903, built on h3 v2), with breaking API changes from Nitro 2 (the engine of Nuxt 3 and 4). Before applying any Nitro recipe, check the installed version in the project's `package.json` and lockfile; for a Nitro 2 project (or a Nuxt 3 or 4 project) treat these files as guidance only and check the official Nitro docs. The AdonisJS files (omakei, a small repository) are one author's opinionated layering (controllers, services, repositories, actions, DTOs) for AdonisJS v6, not official guidance; check framework facts against adonisjs.com. Section 17 (queue example) of `adonisjs-architecture/references/code-examples.md` uses obsolete v5 `@ioc:` imports: do not copy it. The AdonisJS `.ts` and `.yml` example files are text to read, never to run. Links in the NestJS and AdonisJS files written as `../<skill>/SKILL.md` no longer resolve (the file is now `SKILL.upstream.md`): open that name in the same folder.

With the workflow skills: `backend-api-safety` before adding or changing an endpoint or data write, `api-and-interface-design` for a contract, `security-and-hardening` for auth, secrets and input, `investigate-first` for a bug, `surgical-patch` for a small fix, `lean-build` for a new feature; `discover-database`, `discover-caching` and `discover-testing` for those topics.
